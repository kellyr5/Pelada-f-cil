# 🤝 Contribuindo para o Pelada Fácil

Obrigado por considerar contribuir com o Pelada Fácil! Este documento fornece diretrizes para contribuir com o projeto.

## 📋 Código de Conduta

- Seja respeitoso e inclusivo
- Aceite críticas construtivas
- Foque no que é melhor para a comunidade
- Mostre empatia com outros membros da comunidade

## 🚀 Como Contribuir

### 1. Reportar Bugs

Se você encontrou um bug:

1. Verifique se o bug já foi reportado nas [Issues](https://github.com/seu-usuario/pelada-facil/issues)
2. Se não encontrou, crie uma nova issue com:
   - Título descritivo
   - Passos para reproduzir
   - Comportamento esperado vs atual
   - Screenshots (se aplicável)
   - Ambiente (navegador, OS, etc.)

### 2. Sugerir Melhorias

Para sugerir novas funcionalidades:

1. Abra uma issue com a tag `enhancement`
2. Descreva claramente a funcionalidade
3. Explique por que seria útil
4. Forneça exemplos de uso

### 3. Contribuir com Código

#### Setup do Ambiente

```bash
# 1. Fork o projeto
# 2. Clone seu fork
git clone https://github.com/seu-usuario/pelada-facil.git

# 3. Crie uma branch para sua feature
git checkout -b feature/nova-funcionalidade

# 4. Faça suas alterações
# 5. Commit suas mudanças
git commit -m "feat: adiciona nova funcionalidade X"

# 6. Push para o GitHub
git push origin feature/nova-funcionalidade

# 7. Abra um Pull Request
```

#### Convenções de Código

**HTML**
- Use indentação de 4 espaços
- Sempre use tags semânticas
- Adicione atributos `alt` em imagens

**CSS**
- Organize por seções
- Use variáveis CSS para cores e espaçamentos
- Siga a metodologia BEM quando apropriado
- Mobile-first approach

**JavaScript**
- Use ES6+ features
- Escreva código limpo e comentado
- Siga o padrão de nomenclatura camelCase
- Adicione JSDoc quando necessário

#### Commits

Seguimos o padrão [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: nova funcionalidade
fix: correção de bug
docs: alteração na documentação
style: formatação, ponto e vírgula, etc
refactor: refatoração de código
test: adição ou modificação de testes
chore: atualização de tarefas, build, etc
```

Exemplos:
```
feat: adiciona sistema de notificações
fix: corrige erro no formulário de cadastro
docs: atualiza README com instruções de deploy
style: formata código seguindo ESLint
```

### 4. Pull Requests

Ao criar um Pull Request:

1. Preencha o template fornecido
2. Descreva as mudanças realizadas
3. Referencie issues relacionadas
4. Adicione screenshots (se aplicável)
5. Aguarde o code review

**Checklist antes do PR:**
- [ ] Código segue os padrões do projeto
- [ ] Comentários adicionados em código complexo
- [ ] Documentação atualizada
- [ ] Testes adicionados/atualizados
- [ ] Build passa sem erros
- [ ] Testado em múltiplos navegadores
- [ ] Responsivo (mobile, tablet, desktop)

## 🎨 Design Guidelines

- Mantenha a paleta de cores existente
- Use componentes consistentes
- Siga princípios de UX/UI
- Garanta acessibilidade (WCAG 2.1)
- Otimize imagens e assets

## 📱 Responsividade

Teste em pelo menos:
- Chrome (Desktop e Mobile)
- Firefox (Desktop e Mobile)
- Safari (Desktop e Mobile)
- Edge

Breakpoints:
- Mobile: < 768px
- Tablet: 768px - 1024px
- Desktop: > 1024px

## ⚡ Performance

- Minimize CSS e JavaScript para produção
- Otimize imagens (WebP quando possível)
- Use lazy loading
- Evite bibliotecas desnecessárias
- Mantenha bundle size baixo
